# 基础设施与部署笔记（Go 项目）

## 容器运行时与数据库运行（速记）

- 核心结论：
  - containerd 与 Docker 都是“容器运行时/容器运行环境”引擎。
  - 不是把 MySQL/Redis “安装在它们上面”，而是“用它们来运行 MySQL/Redis 的容器镜像”。

- 概念：
  - Docker：带 `docker` CLI，开发/本地调试/CI 常用，可构建/运行/推送镜像。
  - containerd：更底层精简，K8s 节点常用运行时；配 `nerdctl`/`crictl` 操作；兼容 Docker 镜像格式。

- 正确的运行方式（基于镜像，而非传统安装）：
  - 数据需持久化挂载宿主机目录（避免容器重建丢失数据）。
  - Docker 示例：
    - MySQL
      ```bash
      docker run -d --name mysql \
        -e MYSQL_ROOT_PASSWORD=pass \
        -p 3306:3306 \
        -v /data/mysql:/var/lib/mysql \
        mysql:8
      ```
    - Redis
      ```bash
      docker run -d --name redis \
        -p 6379:6379 \
        -v /data/redis:/data \
        redis:7
      ```
  - containerd（nerdctl）示例：
    ```bash
    nerdctl run -d --name mysql -e MYSQL_ROOT_PASSWORD=pass -p 3306:3306 -v /data/mysql:/var/lib/mysql mysql:8
    nerdctl run -d --name redis -p 6379:6379 -v /data/redis:/data redis:7
    ```

- 何时用哪一个：
  - 本地开发/CI：Docker 更方便（生态与命令丰富）。
  - 生产（K8s 集群）：节点使用 containerd/CRI-O，K8s 负责拉取并运行镜像（无需安装 dockerd）。

## 容器与编排

- 容器运行时（运行容器的“引擎”）：
  - Docker：开发/CI 常用，命令好用；镜像构建、push/pull 便捷。
  - containerd：K8s 生产常用，更精简；兼容 Docker 镜像格式；配合 nerdctl/crictl 使用。
  - CRI-O/Podman：同属主流运行时/工具，兼容 OCI 标准。

- Kubernetes（K8s）：
  - 作用：调度/编排/扩缩容/滚动升级/健康检查/服务发现。
  - 不直接“调试/构建”镜像；节点上通常只需 containerd（不必安装 dockerd）。
  - 运行工作负载前提：应用以“容器镜像”形式交付。

- docker-compose vs K8s：
  - docker-compose：单机多容器编排，适合本地开发/小规模部署。
  - K8s：集群级编排，适合生产环境与弹性伸缩。

## 镜像构建 / 推送 / 拉取

- 构建 & 推送（开发/CI）：
  - docker build/push，或 buildah + skopeo，kaniko（K8s 内构建），crane 等。
- 拉取（生产节点）：
  - 由 K8s 通过底层运行时（containerd/CRI-O）自动 pull；也可用 nerdctl/crictl 手动操作。

## 数据库与中间件（MySQL/Redis）

- 推荐容器化运行：
  - 示例（Docker）：
    - MySQL: `docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=pass -v /data/mysql:/var/lib/mysql mysql:8`
    - Redis: `docker run -d -p 6379:6379 -v /data/redis:/data redis:7`
  - 示例（containerd/nerdctl）：命令同理，用 `nerdctl run ...`。
  - 关键：持久化必须挂卷（宿主机目录/云盘），避免容器重建丢数据。
- K8s 上运行：使用 StatefulSet + PVC，或采用官方 Operator（如 MySQL/Redis Operator）。

## 本项目安全与认证

- 密码存储：
  - 使用 bcrypt（带随机盐，多轮哈希），安全性高；不要使用 MD5/SHA1 直接存储。
- JWT：
  - 无状态令牌，不入库。服务端用签名密钥校验签名与过期时间即可。
  - 前端存储：推荐 HttpOnly/Secure Cookie 或（移动端）安全存储；请求时附带。

## 部署到 AWS（小成本建议）

- 起步方案：
  - EC2 + systemd 直接运行二进制（最省资源，~$10–$15/月）
  - 或 Elastic Beanstalk（省心托管），或 ECS Fargate（容器无服务器）。
- 数据库：
  - 成本敏感：自管容器化 MySQL/Redis（记得持久化与备份）。
  - 托管：RDS/ElastiCache（更省运维，成本更高）。
- 备份：
  - 定期 mysqldump；在本项目已实现每周备份与清理旧备份（见 utils/）。

## 运行与优雅关闭（Go）

- 建议：
  - 提供健康检查端点（/healthz）。
  - 支持优雅关闭（处理 in-flight 请求，超时退出）。
  - 合理的 DB 连接池参数（MaxOpen/MaxIdle 等）。

## 术语速查

- 容器（Container）：共享宿主机内核的进程级隔离单元，非虚拟机。
- 运行时（Runtime）：运行/管理容器的底层程序（如 containerd、dockerd、CRI-O）。
- 编排（Orchestration）：K8s 对大量容器的调度、扩缩容、发布与治理。
- OCI：开放容器标准，保证镜像/运行时互通。
